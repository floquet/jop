They are not, by themselves, concerns, deficiencies, or risks.
6. Cross-Product/Cross-Function Integration Observations

Observations should be supported by objective evidence and reflect the maturity of cross-functional planning, the visibility of interdependencies, and the Government's confidence that the assigned product element can be successfully integrated into the overall program.

4. Concerns and Risks Observed
Document the most significant concerns identified during the assessment and any associated risks that could reduce confidence in the contractor's planning maturity and readiness or adversely affect future planning, integration, or program execution if not addressed.
Concerns should be supported by objective evidence and identify observed weaknesses, gaps, inconsistencies, or uncertainties that warrant additional management attention. Risks should describe the potential consequences if those concerns remain unresolved.
Not every concern creates a program risk, and not every identified risk is currently affecting program execution. The purpose of this section is to identify issues that warrant Government visibility, follow-up, or corrective action as planning continues to mature.
Definitions
Concern: An observed weakness, gap, inconsistency, or uncertainty that may reduce confidence in the contractor's planning maturity and readiness.
Risk: A potential future consequence that could adversely affect planning, cost, schedule, technical performance, integration, PMB implementation, or program execution if a concern is not addressed.
Concern 1 (WBS Index Shift - 1.16.05 vs. 1.16.04):
The contractor has coded this IFC 4.0 control account under WBS 1.16.05.23. The WBS Dictionary designates 1.16.5 for IFC 5.0. All IFC 4.0 tasks must reside under WBS 1.16.4 (Full Launch Capability).
Risk 1:
This mismatch will corrupt program cost-reporting structures (CSDR and IPMDAR), resulting in the mistaken aggregation of IFC 4.0 target catalog development costs under the IFC 5.0 budget.
Concern 2 (System-Level Targeting Dependency Risks):
The silo-based target catalog software is functionally dependent on targeting files generated by ground-based systems.
Risk 2:
Because the software WBS is structurally desynchronized from the ground-based targeting hardware design elements, a misalignment between the ground target file formats and the silo's catalog database structure may go undetected, leading to integration failures during Hardware-in-the-Loop (HWIL) testing.

Question 1: How does the "Fixed Launch Silo Target Catalog" integrate with the "Fixed Control Node Target Catalog" (1.16.05.24) and the "Wing-Wide Target Catalogs" (1.16.05.25)? Are there shared data schemas?
Follow-Up 1: Contractor to provide the software architecture model description or SSDD showing the target catalog database schema and interface boundaries.
Question 2: Will the contractor present a unified WBS realignment proposal to map all 1.16.05.xx IFC 4.0 accounts back to the 1.16.04.xx (or government-aligned 1.16.4.xx) branch?
Follow-Up 2: Contractor to submit a revised RAM reflecting the corrected level-3 parent mappings for the entire software suite before PMB baseline lock.
